# OPC UA TUI 一键扫描与快照导出

主界面按 **Ctrl+E**，可直接进入一键导出，无需先打开工作区。也可在 OPC UA 四窗工作区按 B 打开扫描视图，然后按 **x** 导出当前服务，或 **X** 选择集合中的扫描请求。打开窗口、查看范围、取消确认都不连接服务器。

## 一次确认，顺序处理

1. 勾选集合中明确配置为 `protocol: opcua`、`action: scan` 的请求，或者切换到当前服务。
2. 填写一个**尚不存在的新目录**，其父目录须已存在。
3. 预览全部将连接的请求：当前 profile、已解析端点、根 NodeId、深度/节点/每节点引用上限、读值批次、每服务总超时、安全策略、安全模式和认证方式。
4. 确认“开始只读扫描并导出”。依次对每个请求执行扫描、选取全部已发现 Variable、批量读值，以及分别输出 CSV、JSON。
5. 查看结果页中的 success、partial、fail 与每个文件状态；目录内的 `summary.json` 汇总逐服务结果、时间与错误。按 Esc 返回，按 i 可再次查看本次导出结果。

列表严格限定于当前集合中的 scan 请求，不进行网络探测或自动发现其他服务，不执行集合里的 write/call/subscribe。相同端点的多个具体请求仍分别处理，不按端点合并身份、证书、信任设置或根范围。集合请求按当前 profile 解析后冻结在确认预览中；不能解析的请求会明确列为跳过/fail，其余请求可继续。

当前服务模式使用扫描工作区中可见的根和扫描限制；集合模式使用各 scan 请求自己的根、`max_depth`、`max_nodes`、`max_references`、`read_batch_size`、`timeout`，不会被当前工作区参数覆盖。提供了无效参数会报错，不静默改成默认值。

## 边界与安全

- 默认 `max_depth: 0` 表示不限深度，仍受节点、引用与总超时约束。缺省 `max_nodes: 10000`、`max_references: 1000`、`read_batch_size: 100`、`timeout: 2m`。
- 可配置最大 100000 节点、每节点最多 100000 引用、读值每批最多 1000 项。超过 10000 个 Variable 时自动拆为多个只读动作，保留全部已发现变量，不静默截断。
- 每个服务的 timeout 是扫描及所有读组的总预算。一个服务失败、超时或达到限制，不阻止处理后续明确选择的服务。
- 扫描后保存 NamespaceArray 指纹；每个读组都要求引擎验证相同指纹。指纹缺失、无效或服务端命名空间变动时不使用旧 NodeId 误读，不把结果计为成功。
- 沿用每个请求已有的认证、客户端证书、服务端信任/指纹、安全策略和模式，不自动降级。缺省仍是项目既有的安全配置。需要无加密连接时必须由用户在其配置中显式授权相应设置。
- `--read-only` 可正常使用该功能，因为网络操作仅为 scan/read；本地保存导出文件不属于设备写入。
- 请求参数、密码、密钥内容不会写入快照。文件名仅由顺序编号及安全处理后的请求 ID 生成，不使用端点作路径。
- 仅新建目录（0700）与文件（0600）；已有目录、文件或同名符号链接均拒绝覆盖。

## 不完整结果、取消与输出错误

每服务导出 `001-request-id.csv` 与 `001-request-id.json`，使用现有快照编码器保留整数精度、数组、值类型、源/服务端时间戳、观察时间、状态与错误。未读取的变量仍保留一行，明确标为未读取。`has_value` 表示 DataValue 中存在 Variant，能区分有效 UA Null 与无 Variant 的 BadNodeIdUnknown/BadUserAccessDenied。

`scan_complete` 仅表示在指定根和限制内扫描完成；值未读、坏状态、读服务失败、NamespaceArray 变化或文件失败均可使整个服务为 partial/fail。汇总中的 `read` 是收到 value 结果的行数（可包含坏状态）；`failed_values` 是其中无有效 Variant、错误或非 Good 的行；`unread` 是未收到 value 的行。

**这些是分批、跨会话、跨服务的逐次观察，不是同一时刻的原子快照。** 应用时间戳反映对应观察，不能将导出时间当成所有变量的同步采样时间。

按 S/F8 取消会停止当前网络操作，不再连接后续请求；已完成文件保留，当前可得观察会用独立、限时的本地写出阶段保存，未开始的请求标 partial。Esc 关闭工作区或 Ctrl+C 退出也会取消网络任务并等待本地收尾。操作进行中重复按快捷键不会并发再开任务。输出文件写入、flush、sync、close 或汇总写入失败都会显示；可能不完整的文件不会声称成功。

## 验证范围

自动测试包括注入的连接/读值/命名空间/取消/磁盘故障，以及仅绑定回环地址的真实 OPC UA 测试服务器四请求顺序 scan/read/导出。它们不代表工业端点、现场 PLC、麒麟设备本机运行或生产地址空间的验收，测试不会连接实际现场服务。
