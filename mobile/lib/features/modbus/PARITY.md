## 第一批 TCP 整机测试的范围

测试通过 `adb reverse` 访问 `127.0.0.1:48415` 的合成 Modbus TCP 服务，以及 `127.0.0.1:48416/metrics` 的独立计数服务。初始 holding 寄存器为 0=7、1=42。测试验证启动、打开工作区、导航、布局、缓存趋势和取消写入均不产生设备 I/O，然后明确确认一次类型 FC16 写入，检查计数与回读，再将寄存器 0 恢复为 7。它还检查生命周期恢复不会重放写入，并恢复原测试集合，保存三张 Flutter 截图。

执行后，这些结果只能作为真实线协议经过合成 TCP 夹具的证据，不能代替物理工业设备验收。

## 第二批验证范围

第二批测试由现有 Modbus 注册入口接入下一候选版本，覆盖 M9／M15／M16／M17／M18／M21／M22 的真实 Flutter 操作路径。FC23 的单次事务应同时增加一次读取和一次写入。FC43 提供固定对象 `iotools fixture`、`local-loopback`、`1.0`。单元 2 返回异常 11；只有合法单元 1 请求增加设备 I/O 计数。

本机控制服务只监听 `127.0.0.1:18123`，设备目标固定为 `tcp://127.0.0.1:48415`。必须在 Flutter 页面明确确认启动及写入范围后，测试才访问 `/health`、`/read`、`/write`。错误单元、范围外地址和浏览器 Origin 必须在没有 TCP 写入的情况下被拒绝；停止操作必须关闭监听器。

审计失败测试使用唯一且不存在的应用私有父目录，不申请广泛文件权限。测试结束后恢复寄存器 0=7、1=42、原始集合和本次改动的测试设置。

这一批同时修复 FC23 的 `count`：它等于实际写入字数，与读取数量独立；对应的实际控件回归测试已通过。会话页新增异步完成／失败详情，包含审计打开失败。这些第二批变化不属于首个不可变候选 SHA `19d4b2e948973d64e2014a1570cd26a092e3ef8c`。
